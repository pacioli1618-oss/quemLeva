# Internationalization (i18n)

QuemLeva speaks **pt-BR** (default), **es** and **en**, using [`next-intl`](https://next-intl.dev) 4 with Next.js 16 (`cacheComponents` on).

## How the locale is picked

1. The `QL_LOCALE` cookie, set when the person switches language.
2. Without a cookie, the browser's `Accept-Language` header.
3. If nothing matches, `pt-BR`.

**URLs never carry the locale** (`localePrefix: 'never'`). The event link, `/e/<slug>`, is the same for the whole group, and each person sees the UI in their own language. Under the hood, `src/proxy.ts` rewrites the request to `/<locale>/e/<slug>`. The locale is then a *root param* (`next/root-params`), so pages stay static and cacheable: no page reads `headers()` or `cookies()`.

## Where things live

| Path | What it is |
| --- | --- |
| `src/i18n/locales.ts` | Locales, default locale, each language's name and suggested currency. **Single source.** |
| `src/i18n/routing.ts` | next-intl routing config (no prefix, `QL_LOCALE` cookie) |
| `src/i18n/request.ts` | Loads the current locale's messages and sets the default time zone |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `useRouter` and `redirect`. Use these, not the `next/*` ones. |
| `src/i18n/units.ts` | Unit and category codes, plus `useFormatAmount()`: "4 sacos", "4 bolsas", "4 bags" |
| `src/i18n/dates.ts` | `useFormatEventDate()` (wall-clock, no time-zone shift) and `useFormatMoney()` |
| `src/i18n/errors.ts` | Turns `ql_*` RPC error codes into translated messages |
| `src/proxy.ts` | Detects the locale and rewrites to `/<locale>/…` |
| `src/app/[locale]/` | Every page. The root layout lives here. |
| `src/types/next-intl.d.ts` | Typing: an unknown key or a missing argument fails the build |
| `messages/<locale>.json` | The copy. `pt-BR.json` is the source. |
| `scripts/check-messages.mjs` | `npm run i18n:check`: keys, ICU syntax and arguments |

## Rules for writing copy

- **Always ICU, never concatenation.** Write `"{count, plural, one {falta {amount}} other {faltam {amount}}}"`, not `"faltam " + n`. Word order changes between languages.
- **Plurals with decimals work:** "falta 1,5 kg" in pt-BR, "faltan 1,5 kg" in es, "1.5 kg to go" in en. Each language's plural rules decide.
- **Units and categories are codes.** Store `unit = 'bag'` and `category = 'meat'`. Free text ("travessa") is shown as typed.
- **User content is never translated.** Event title, typed items and notes appear as written.
- **Event date and time** are wall-clock values. Use `useFormatEventDate()`, which formats in UTC to avoid shifting the time zone.
- **Money** uses the event's currency (`events.currency`), not the browser's. An Argentinian viewing a barbecue in São Paulo sees expenses in reais.
- **Neutral Latin American Spanish**, using "tú". Local terms live in `messages/es.json` ("Asado", "bolsa de hielo"). An `es-AR` variant with "vos" would be a new locale.
- **Naming** of namespaces and keys follows `docs/conventions.md`, section 8.

## What the event stores

`quemleva.events` has three locale-related columns:

- `locale`: the creator's language. Used for A4 printing, the Spliit group text and the suggested list.
- `currency`: an ISO 4217 code, defaulting to the locale's suggested currency (`locales.ts`).
- `kind`: `barbecue`, `lunch`, `birthday`, `christmas` or `other`, translated in `EventKind`.

`ql_create_event` takes `p_locale`, `p_currency` and `p_kind`. `ql_get_event` returns all three, and `ql_update_event` accepts them in the patch.

## Adding a locale

1. Add the code to `locales` and `localeNames` in `src/i18n/locales.ts`, plus its suggested currency.
2. Copy `messages/pt-BR.json` to `messages/<new>.json` and translate it.
3. Run `npm run i18n:check` and `npm run build`.
4. Add the code to the `check (locale in (...))` on `quemleva.events` in a new migration.

## Known limits

- **Server Actions and Route Handlers** have no root params. Pass the locale explicitly there: `getTranslations({locale, namespace})`.
- **Per-locale SEO:** without URL prefixes there is no separately indexable page per language. If the landing page needs that, it can get its own prefixed routes (`/es`, `/en`) without changing event links.
- **Barbecue calculator:** quantities and cuts change by country (picanha vs. vacío). When it exists, list templates live per locale (`src/i18n/templates/<locale>.ts`), not as messages.
